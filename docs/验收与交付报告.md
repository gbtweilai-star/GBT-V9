### 9.2 账本迁移方案（新文档）
`audit/PG-MIGRATION.md`：**四步加法**——①建表（schema_pg.sql 幂等）②双写过渡（`DualLedger` 主/影同 event_id）③一次性回填（2000 行/批，`ON CONFLICT DO NOTHING` 可重跑，`--verify` 打一致性）④切换（两个环境变量）。
调参全部真实存在：`PG_MINCONN/PG_MAXCONN`（新增，池上下限）、`PG_SLOW_MS`、`PG_LONG_TX_S`。
实测：`DualLedger` 双写 → 主/影 counts 同幅、读透传主库；回滚路径与"PG 期间行不在 SQLite"的诚实说明都写进文档。

### 9.3 传感器 SQL 方言（新模块）
`senses/sqldialect.py`：`is_pg()` 判定 + `txn()`（事务+游标，兼容 sqlite3 游标无上下文管理）+ 双方言分流。
voice/mic 四张表（voice_jobs / transcripts / mic_segments / mic_events）在 SQLite 下：`?` 占位符、`REAL` epoch、`datetime('now')`；
PG 下：`%s`、`TIMESTAMPTZ`+`to_timestamp()`、`now()`。filter 用 `(? IS NULL OR …)` 常量 SQL，**零动态拼 SQL**。
实测：SQLite 下建表/写入/检索全通；面板 `/api/senses` 读到 `voice:{queued:2, failed:1}` 真数据。

### 15.3 授权模型：授权是唯一闸门（不再被硬编码黑名单挡住）

### 16.1 原生视觉"看电影每一帧都不丢"（`senses/frame_lock.py`）
- **性能路径三改**（都是实测驱动，不是拍脑袋）：
  ① 早期实现每帧新建 mss + PIL 编码 PNG → 只有 **8fps**（元凶）；
  ② 复用 mss 实例 + 原始像素直哈希 → **24~30fps**；
  ③ 优先 **dxcam(DXGI 桌面复制)** + blake2b128 逐帧指纹（落盘帧再补 sha256）→ **~35fps**（本机 1920×1080 @125%）。
- **自校准**：`calibrate()` 先量可达帧率，再按 `VISION_PACE_MARGIN`（默认 0.75）定节奏；
  节拍"睡到临界 + 最后 1~2ms 自旋"（Windows sleep 精度仅 ~15.6ms，纯 sleep 必迟到）。
- **判定语义（关键）**：`on_time`（零丢帧且按时率≥98%）/ `no_loss`（帧都在、节奏有抖动）/
  `dropped`（真有缺口）—— **迟到 ≠ 丢帧**，不许混为一谈。
- 实测（真实屏幕，3 秒）：**78 帧、span=78、gaps=0、missing_in_span=0、序号连续 → `no_loss`**，
  p50 取帧 17ms、后端 `dxcam`、校准 34.6fps。
- 与 `senses/devour.py` 桥接：`merge_into_devour_index()` 把本轮 gap 并入断档账，避免两处各记一份。

### 16.2 触手专属永久邮箱 GBT-D1 … GBT-D100（`core/mailbox_fleet.py`）

### 23.1 第二轮：3D 姿势轴向修复（同日晚）

第一轮渲染里"头是菱形、四肢乱转"，这轮挖到**两个真根因**（都是渲染出来亲眼看才发现的）：

1. **单位错（最隐蔽）**：我们的 `angle()` 用 `math.atan2` 出的是**弧度**，而 `_wrap180()` 是按**度**写的。
   大动作的增量本来 -212.5°，在弧度里是 -3.708，被 `_wrap180` 当成 **-3.708 度** → 所有大幅动作被压成
   "几乎不动"，看着像骨头各自乱转。修法：`math.degrees()` 之后再 wrap；Blender 侧再 `math.radians()`
   喂四元数。**新增回归测试**：动作增量必须是度量级（欢呼手臂 > 90°），待机 < 15°，左右镜像互为相反数。
2. **盒子轴错**：头/发的 `add_part` 我传了"对角两点"，而 `push_box` 把 a→b 当**盒子轴** →
   头被摆成 51° 斜的菱形（渲染里那个白菱形就是它）。修法：给竖直轴两点 + 厚/深作宽高。

加上第一轮已修的"pose 必须相对父骨（世界增量 − 父骨增量，并换算到**父骨空间**再转四元数）"，
现在 `cheer` 渲染确认：**双耳在上、双臂举成 V、头盒正立** —— 3D 动作真的摆出来了。
测试 9 项（新增单位回归与 wrap 判据）；产物 `state/blender/*.png` + `*.glb`（含动画）。

### 23.4 第四步：3D 逼真度打磨（零成本、不出网）与它的天花板

**做了什么**（四路一起上，缺一样都会露馅）：
- 渲染：EEVEE Next + 光追 AO/阴影 + 64 采样 + **AgX 电影色** + 渐变影棚背景 + **地面接影**（人才"站得住"）。
- 镜头：**透视 3/4 机位**（62mm 等效）+ **景深虚化背景**（f/2.6）——照片感的最大来源。
- 光：三点光（暖主光 / 冷补光 / 轮廓光），能量按模型尺度换算。
- 材质：皮肤**次表面散射**+噪声凹凸、西装/衬衫/裙**绒面 Sheen**+布纹、皮鞋低粗糙高光、指甲 0.14、眼睛（眼白 0.10 / 瞳 0.06）、唇、粉内耳。
- 形体：**五官**（眼白+瞳+睫毛线+眉+鼻+唇）、7 片刘海 + 2 束侧发 + 5 束波浪后长发、弯曲兔耳带粉内衬、躯干分段收腰、西装翻领/领口/领带/衬衫前襟、裙摆微褶、**掌+四指+拇指+长指甲**、高跟（靴筒+鞋底+细跟）、绒球尾。
- 工程：bpy 脚本改为独立模板 `templates/blender_scene.tmpl`（占位符注入），不再挤在 f-string 里。

又踩四坑：相机**位置**必须与朝向一起复位（否则序列帧整批空白）；刘海落到眼睛高度会罩住整张脸；肘/膝加关节球会变"串珠"、鞋不加靴筒就与小腿脱节；光太强会把深灰西装照成白色。

**天花板（如实说）**：程序化"胶囊+球+管"的极限是**风格化人偶**，达不到原图那种写实自然。要写实只有三条路：
① 一次性下载开源写实人形基础网格（MB-Lab / MakeHuman base mesh / CC0 模型）→ 用我们已有的 32 动作驱动，**零成本但需一次出网票**；
② 图生3D（需 CUDA 机器或云，需出网票）；
③ 手工建模（不可脚本化，工时长）。本轮三者都未获授权，故停在人偶级。

## 24. 云上图生3D：按参考图生成写实 3D 数字人（2026-10-07）

主人要求："我要一摸一样的，本地跑不动就按照云插件部署，必须达到我要的效果。"

**为什么走云**：本机 `torch 2.12.0+cpu`、显卡 AMD RX 6500M 4GB（无 CUDA），TripoSR/SF3D/Hunyuan3D
这类图生3D 本地跑不动。**本机已有 Tripo3D OpenAPI 凭据**（`~/.tripo/config.json`），于是把
"云上生成 + 本地渲染验收"接成一条链（`core/tripo.py` + `templates/blender_asset.tmpl`）。

**凭据上踩的两个坑（都真踩过）**
1. 环境变量 `TRIPO_API_KEY` 里存的是 `tcli_` 开头的**客户端 ID**（不是密钥），CLI 优先读它 → `whoami` 401。
   正确做法：用 profile 里的 `tsk_` 密钥，并在跑 CLI 时把 `TRIPO_API_KEY` 从环境里摘掉。
2. 两个域名并用：CLI 走 `openapi.tripo3d.ai`，而 `/user/balance` 只在 `api.tripo3d.ai` 上存在。

**链路（云端生成 + 本地渲染）**
1. 从参考图切出**完整人体正视图**（第一次只切到大腿 → 出来是半身像，已修：用亮像素定位白色高跟定底边）。
2. 云端 `image_to_model`(30) → `texture_model`(10) → `animate_rig` 自动绑骨(25)。
3. `image-to-image` 给正视图**加兔耳**(5)、给背视图**加兔耳+绒球尾**(5) —— 参考图的兔耳与尾巴只在
   "变身"格里，原正视图没有，所以先编辑出带特征的视图。
4. `multiview-to-model` 用正+背两视图(30) → 几何带上兔耳与绒球尾；再 `animate_rig` 绑骨。
5. 本地 Blender 影棚渲染：透视景深 + 三点光 + 地面接影 + AgX + 转台 8 角度 + 脸部特写。
   余额 365 → 约 105。

**工程化**
- `core/tripo.py`：能力位（`status` 只读 / `make` 支持单图与多视图 / `render_asset` / 路径安全），
  过防偷懒钩子 + 固化。
- `templates/blender_asset.tmpl`：外部 glb 的影棚渲染模板。**正面判定用脚尖方向**（最初用"头后头发
  更重"的启发式，戴上兔耳后会判反，渲出来全是背面，已改）。
- 接口：`/api/tripo/status|models|labels|frame|make|render`；`/digital-human` 的 3D 卡换成**真 3D 形象**
  （转台可拖、主图、脸部特写、模型/标签下拉、用这个模型重渲染），并写明"几何贴图来自云端、渲染在本地"。
- 测试：`tests/test_tripo_capability.py` 7 项（状态不泄漏密钥 / 跑 CLI 去掉客户端 ID / SSRF 白名单 /
  取图名防穿越 / 接口 / 页面），并把 blender 那条过时的页面断言对齐到新卡片。

**如实说明的差距**：这是 AI 从 2D 图**重建**的 3D —— 衣着、发型、兔耳、绒球尾、比例、姿势都对上了，
但**脸部细节不如原图那张精修插画**；预设动作（`preset:walk`）试过一次未通过，没有再猜（避免白扣额度），
模型本身已绑骨，动作可在 Blender 里接。交付对照图：`state/tripo/render/DELIVERY.png`。
