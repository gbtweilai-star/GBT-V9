## 7. 不整齐清单（带证据 · 按影响排序）

### P0 —— 照文档跑不起来 / 没有回滚网
1. **`requirements.txt` 不是依赖清单**（已逐行核对，59 行）：内容是「3 行系统依赖 + 环境变量模板 + 安装步骤」，
   **没有任何一个真 Python 依赖**（readme 声称的 fastapi / uvicorn / pydantic / mss / pillow / numpy /
   pyautogui / boto3 / botocore / openai 全不在）。
   而 `README §2` 说它们「见 requirements.txt」、`install.sh` 第 2 步直接 `pip install -r requirements.txt`。
   → 谁照文档从零装环境，**第一步就断**。
2. **没有版本控制**：`.git` 不存在（`.gitignore` 已备好，能挡住 state/ data/ devoured/ release/ 与密钥）。
   现在任何「整理/删除」都没有回滚网 —— 这是所有清理动作的前置条件。

### P1 —— 旧件没退役（LAYOUT 第一条铁律的漏网）
3. **`desktop/release/` 里 4 个过期安装包 ≈ 1,032 MB**（0.13.6 / 0.13.7 / 0.13.8 / 0.13.9 + blockmap），
   而 `desktop/package.json` 已经是 **0.14.0**。
   根因：`core/retire.py` 的 `JUNK_PATTERNS` **只扫 `state/` 下的模式**，管不到 `desktop/`。
4. **`state/` 里的测试垃圾扫不到**：`pytest-ble-tmp / dc / opt / pg / tf / x / y` 共 7 个目录 26 文件，
   而模式表里写的是 `_pytest_tmp`、`pytest-pipe-tmp` —— **名字对不上，永远扫不到**；
   另有 `_archive_placeholders`（184 件，打包占位符）、`_archive_logs`（4 件）同样不在模式表内。
5. **`devoured/` 22 个子目录，只有 `t1-eye` 是活的**（`DEVOUR_DIR` 默认值）。
   其余 21 个是历次实验残留：`_t1…_t7`、`_t_vision/_t_vision2/_t_vision3`、
   `vision`（16 张真帧，被 `core/alt_impl.py` 当兜底素材 → **要留**）、`vision2…vision8`（只剩孤儿 `index.jsonl`）。
   `README` 的目录树只承认 `t1-eye`。

### P2 —— 孤岛与文档漂移
6. `src/octop/api/branding.py`（+ pyc）：**孤岛**，全仓无 `from src`/`import src`（只有 `tools/brand_scan.py` 把字符串 `"src/octop"` 当扫描词）。
7. 空/杂件：根 `__pycache__/`（conftest 的 pyc）、`voice_cache/`（空目录，且已在 .gitignore）、`.tripo/context.json`。
8. 文档漂移：`README.md` 描述的仍是「触手工程 26 件目录树」，与现在「35 目录 / 21 页面 / 277 路由」的复合工程不符；
   `docs/` 六份文档（LAYOUT · MAPPING · PREFLIGHT · 认知系统架构 · 验收与交付报告 76KB · 桌面应用V9交付）**没有总入口**，README 也不索引它们。
9. `tools/selfcheck.py` 的 `skip_parts` 没有排除 `node_modules` —— 语法检查会走进 `desktop/node_modules` 的第三方 Python
   （实测 SyntaxWarning 就来自 `dmg-builder/vendor/dmgbuild/colors.py`），只是恰好没编译失败。
10. 归档口径三处：`_archive/`（仓根）、`state/_archive_logs`、`state/_archive_placeholders` —— 同名不同义。
